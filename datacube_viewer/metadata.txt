about=Load GeoZarr datacubes, plain Zarr stores, NetCDF files and Icechunk repositories
    as raster layers in QGIS.
    Sliders in a dock panel step through the non-spatial axes of the cube (time, sensor,
    etc.) and redraw the layer as you drag. The plugin reads directly from
    plain Zarr v3 stores and NetCDF files as well as Icechunk repositories (local, S3,
    GCS, Azure, R2 or HTTP), resolves the CRS from zarr-conventions "proj:code" or CF
    grid mappings, and switches between pyramid levels as you zoom. Icechunk branches,
    tags and snapshots can be selected at load time and changed afterwards without
    re-adding the layer.
    .
    ONE MANUAL STEP AFTER INSTALL: this plugin needs the "zarr" (>=3) Python package
    for Zarr stores and/or "netCDF4" for NetCDF files, and QGIS's Plugin Manager does
    not install Python packages. After installing, open Raster > Datacube Viewer >
    Install Python Dependencies... - it detects your operating system and QGIS
    build, shows the exact command to run, where to run it, and the interpreter it
    targets, and on Windows, macOS and Linux can run it for you with "Install now".
    That installs with pip --user and pins every package QGIS's Python already has,
    so it never upgrades or replaces one of them. "icechunk" is optional and only
    needed for Icechunk repositories. zarr and icechunk require Python 3.11 or newer.
    On Linux, QGIS uses the system Python, which can be older (Python 3.10 on Ubuntu
    22.04); the README describes using QGIS from conda-forge instead.
    .
    Originally developed by EODC (https://eodc.eu) as "GeoZarr Viewer". MIT licensed.
    This is a renamed fork carrying local changes; it is not the EODC release.

changelog=0.5.0
    - QGIS 4: the plugin runs on QGIS 4 (Qt6) as well as on QGIS 3.40 and
      later, from the same code.
    - Timeseries: right-click a datacube layer on the map, "Datacube Viewer:
      Show Timeseries", and pick an axis. The pixel's values along it are
      added to the new Timeseries panel, with a marker on the map in the
      line's colour. Each pick adds a line, holding the other axes where the
      layer's sliders are; the Plot Pixel tool adds one per click. Hovering
      reads out every line, the wheel zooms, and the values export as CSV.
    - Subsets: each non-spatial axis in the Add Datacube Layer dialog can be
      cut down to a range (time and numeric axes) or to chosen values
      (sensors and other named axes). The cube panel's sliders, its search
      and the colour range only visit the kept slices. A playhead on the
      range slider picks the slice the layer opens on.
    - Ctrl+drag moves the subset sliders and the cube panel's sliders slowly
      enough to reach every step of a long axis. The speed is under
      Settings > Options > Datacube Viewer.
    - The cube panel shows a progress bar while a large cube's colour range
      is fitted, and the wait cursor shows while layers are added.
    - Fix: several layers of one NetCDF file open quickly together; the
      colour range scan of the first no longer holds up the others.
    - Fix: Icechunk's empty first snapshot, which every repository has, is
      no longer offered in the snapshot slider and the snapshot list, where
      it could only fail to open.
  0.4.0
    - Exact colour range: a new layer's range comes from every pixel at full
      resolution, computed in the background with progress in the QGIS task
      bar. A cube past 100 million pixels is read from whole slices spread
      evenly through it, and the cube panel says how many. "Full scan of
      every slice" in the dialog and the panel reads everything regardless.
    - The legend's colour bar shows <= or >= at an end where the slice on
      screen goes past the range.
    - Settings > Options > Datacube Viewer sets the default method (min/max,
      cumulative count cut, mean +- std dev), the accuracy (exact or
      estimated) and the pixel budget. Each layer's own Symbology settings
      win over them.
    - Bilinear resampling next to nodata draws a pixel when any neighbour
      has data, as GDAL does. "Bilinear next to nodata" in the options asks
      for half or all of them instead.
    - Fix: scaled variables (CF scale_factor / add_offset) show physical
      values everywhere, not only on the map. Statistics, the colour range
      and Identify no longer work on the stored integers.
    - Fix: "average" and "bilinear" resampling no longer blend fill values
      into neighbouring pixels, which could turn the edge of a no-data area
      into values that passed as data.
  0.3.0
    - Drag and drop: a Zarr store, NetCDF file or Icechunk repository dragged
      onto QGIS opens in the Add Datacube Layer dialog, already connected.
      Under Settings > Options > Datacube Viewer > Drag-and-drop behavior, each
      kind can instead add every variable as a layer, or be left to QGIS (GDAL),
      with a separate choice for a batch of several stores dropped at once.
    - Stores of a batch that open the dialog share one when they match (same
      datasets, variables and axes), and what is added from it is added from
      each; otherwise they open one after another, with Skip Remaining to stop.
    - Fuzzy search in the slider sidebar and the load dialog: jump to a
      date or axis value, select or add a variable by part of its name.
    - Attributes at the bottom of the slider sidebar: the selected layer's
      variable, axes, dataset and store metadata, with copy.
    - A layer asked for a slice it does not have (an unknown axis, or an
      index outside its axis) is now invalid and says why, rather than
      silently showing another slice. setIndices refuses the same with the
      reason in lastError, and a project whose saved slice the store no
      longer has says so when it opens.
    - The slider sidebar redraws while a handle is dragged, not only when it
      stops moving; "Redraw while dragging" turns that off for slow stores,
      with its default in the plugin's options.
    - The dialog's Add button says Add Layer or Add Layers; the install help
      can copy its check command too.
    - Fix: recent NetCDF files are no longer greyed out as missing in the
      dialog's Location list.
  0.2.0
    - Install now: Raster > Datacube Viewer > Install Python Dependencies...
      installs zarr, netCDF4, icechunk, fsspec and s3fs itself, without
      changing any package QGIS already uses (conda in a conda environment).
    - The slider sidebar opens on the new layer when layers are added from the
      dialog. Turn this off under Settings > Options > Datacube Viewer.
    - Icechunk branches, tags and snapshots in the slider sidebar, kept in step
      with Time Travel.
    - Add / Apply / Close in the Add Datacube Layer dialog: Add closes it,
      Apply keeps it open.
    - A layer can override the store's nodata value through its layer URI.
    - New toolbar icons.
    - Fix: the axis sliders no longer swap order between loads of the same store.
  Earlier versions: see the GitHub releases.
